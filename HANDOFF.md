## What this is

A complete, working 16-page website for **Ember Ridge**, an auxiliary ministry of
**Firebrand Revivalists** in Moravian Falls, North Carolina. Built in one session
from a single source document — *Ember Ridge, Shannon's Vision* — which was the
primary source of truth for all copy, tone and structure.

The core message the whole site is organised around:

> Ember Ridge exists to tend the fire God has entrusted to His people. It is a
> house that ministers first to the Lord, restores people who carry great
> responsibility, and sends them back strengthened for the work of the Kingdom.

## The stack, and why

**Astro 5 + Tailwind CSS v4.** Static output — Netlify serves plain HTML, there is
no server to maintain, and pages ship almost no JavaScript. Chosen over Next.js
because this is content, not an application.

- ~55 KB CSS, ~2 KB JS, no client-side framework runtime
- Fonts self-hosted via `@fontsource` (Cormorant Garamond + Inter) — no external
  font requests, which is also why the Cookie Notice can be as short as it is
- No analytics, no trackers, no third-party embeds
- One `IntersectionObserver` powers every scroll reveal on the site

**Two Tailwind v4 gotchas.** There is no `tailwind.config.js` — every design token
lives in the `@theme` block at the top of `src/styles/global.css`. And `.btn` is
declared as `@utility btn` at the top level rather than inside
`@layer components`, because Tailwind v4 cannot `@apply` a class defined in a
layer and the button variants need to apply it. Moving it back will break the
build.

## Decisions made deliberately — check before reversing

1. **Navigation.** The main menu carries the eight items requested: Home, Vision,
   Story, Ministry, Campus, Leadership, Partner, Contact. *The House of Prayer*,
   *The Place* and *Financial Stewardship* are reached from the footer and from
   contextual in-page links, to keep the top bar calm. Legal pages appear in the
   footer only. This was a judgment call and is fair to revisit.

2. **Logo treatment.** The supplied Ember Ridge and Firebrand logos have black
   lettering that disappears on a black header. Rather than apply a CSS filter
   (which flattens the gold), `*-logo-dark.png` variants were generated by
   remapping the dark, low-saturation pixels to cream while preserving the gold.
   Originals are kept at `public/images/*-logo.png` for light backgrounds and
   print. If a proper dark-background file arrives from a designer, swap it in.

3. **Brand hierarchy.** Ember Ridge is primary everywhere. Firebrand appears as
   "A Ministry of Firebrand Revivalists" beneath the header wordmark and as a full
   logo lockup in the footer attribution. This was explicitly requested.

4. **Gold discipline.** Gold is never a background field — only hairline rules,
   small bullets, borders, small-caps eyebrows and one primary button. Roughly
   three to five gold moments per page. Adding more will cheapen it quickly.

5. **Motion.** One easing curve site-wide, gentle fades, and a slow ambient hero
   gradient. All motion is disabled under `prefers-reduced-motion: reduce`. No
   animation library was added, on purpose.

6. **Mark Burgett's portrait** is a styled SVG placeholder reading "PORTRAIT TO
   COME," and his bio still carries `placeholder: true`. Shannon, Jason and Anne
   now have their own approved bios. Swap the `image` path in
   `src/data/leadership.ts` and drop the flag when Mark's text and photo arrive.

7. **Anne Whaley, J.D.** is the displayed name by explicit decision, even though
   the supplied bio text was headed "Annie Suttles." References inside the bio
   were changed from "Annie" to "Anne" at her request. Do not change either
   without asking.

8. **Hero particles** are generated at build time from a seeded generator in
   `Embers.astro`, so the HTML is byte-identical between builds. Density drops on
   mobile via `hidden sm:block`, which stops the animation rather than merely
   hiding it. Everything is removed under `prefers-reduced-motion`.

9. **Concept images** on Remodel & Grounds are labelled SVG placeholders in
   `public/images/concepts/`. Replacing one is a single `src` change on the
   `<ConceptFigure>`; keep the caption's "(placeholder)" suffix until it is real.

## Not built, on purpose

Each needs a decision before it is added. Do not add unprompted.

- **Online giving.** No donate button, no payment processor. Gated on confirming
  Firebrand's tax status and charitable solicitation registration.
- **Analytics.** None. Adding any requires updating the Cookie Notice and Privacy
  Policy first.
- **Newsletter signup.** None. Would need its own consent language.
- **Application or booking form for stays.** The source document is explicit that
  placements are prayerfully discerned through relationship and referral, not
  publicly marketed. The site invites a conversation instead.
- **Blog, events calendar, sermon library.** Not in the source document.
- **Testimonials or outcome claims.** Nothing that would overstate results.

## Honesty constraints observed

Followed throughout, and worth continuing:

- Nothing was invented. Where the source document was silent, the site either
  omits the claim or marks it for review.
- The lodge **has not been acquired.** All property language describes a vision
  under discernment, not a completed purchase.
- Capital figures are labelled preliminary planning ranges — never bids or
  guarantees.
- No statement about tax deductibility of gifts appears anywhere, because the
  ministry's tax status has not been confirmed.
- The limitation of liability clause in Terms of Use is **deliberately left blank**
  for counsel rather than filled with boilerplate.
- Historical and prophetic references (Herrnhut, Prayer Mountain, the Golden
  Candlestick fellowship, the 1997 prophetic word) are presented as strands of
  testimony to be weighed, not as verified claims.

## Deploy path

Nothing is live. When ready:

1. `git init`, commit, push to a new GitHub repo
2. Netlify → Import an existing project → GitHub. `netlify.toml` declares the
   build command, publish directory, headers and redirects — accept the defaults
3. **Turn on password protection immediately** (Site configuration → Access
   control) so the draft legal pages are not public
4. Update `site` in `astro.config.mjs` and the `Sitemap:` line in
   `public/robots.txt` to the real domain
5. Set form notification recipients under Netlify → Forms →
   `ember-ridge-inquiry`, and decide who may read submissions marked confidential
6. Work the checklist, remove the draft banners from `LegalLayout.astro`, unlock

For a quick look without any of that: `npm run build`, then drag `dist` onto
app.netlify.com/drop.
